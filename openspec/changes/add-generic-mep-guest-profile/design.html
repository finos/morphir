Context

See proposal.md for the motivation. The runner in crates/morphir-mck/src/mep.rs walks one fixed case list per profile, and report-check rebuilds that list from the kit alone. The Python profile in mep/python.rs already has most of the JSON cases, but it fixes the extension id, the language, the target and the generated bytes. WASM guests have no public stdio host yet (finos/morphir-moonbit#297). The native MoonBit CLI runs one as an internal worker: morphir extension worker --abi <abi> --module <wasm> --build-identity <hex>.

Evidence from three guests

Before the design, the same Bool package (ready = true, blocked = false, module main of mck/generic) was sent to three real guests through the worker host. Results:

The v3 IR of the three guests is the same apart from value order and object member order. The v4 IR differs only in the type reference spelling, which IR v4 defines as equal (docs/design/draft/ir/types.md, "Type and Value Shorthand"). The generated files are all different (main.flags, main.py, main.gleam), as expected.

Goals and non-goals

Goals: one kit that qualifies guests of different languages and identities; a plan that follows the guest's claim but cannot be shortened by it; comparison by meaning; a recheck from the stored report alone.

Non-goals: Ion transport, guarantees or evidence (the MoonBit profile covers them); types, records or functions with arguments (the flags language cannot write them); host conversion; a public stdio host (finos/morphir-moonbit#297); changes to the existing profiles.

Decisions

GKP-1. One package, one expected IR, a source set per language

The kit fixes the semantics once: two public Bool constants in module main. Each language gives its own documents for that package and a malformed source. The package is this small because the SDK fixture language can only write Bool constants, and the names are single words so that no naming convention changes them.

"languages": {
  "gleam":   { "documents": [{"uri": "main.gleam", "text": "pub fn ready() -> Bool { ... }"}], "malformed": [...] },
  "morphir-fixture-flags": { "documents": [{"uri": "main.flags", "text": "ready = true\nblocked = false\n"}], ... },
  "python":  { "documents": [{"uri": "main.py", "text": "def ready() -> bool: ..."}], ... }
}

Alternatives: one kit file per language (a list of extensions again, and N copies of the expected IR that can drift); one language-neutral source (no such language exists for these frontends). URIs are relative to the source folder, as finos/morphir-moonbit#294 decided for directory inputs.

GKP-2. The plan comes from the recorded describe claim

The first case is describe. From its result the runner selects the first kit language that the guest claims as a frontend language and a backend target, the IR versions that both its frontend and backend claim, and the model tier. The plan is a pure function of the kit and that one observation, so report-check rebuilds it from the stored report. A guest cannot drop a case: anything it claims inside the profile's scope is tested, and a claim of nothing selectable fails.

describe → (language, versions, modelVersions)
legacy:  initialize(0.1) · initialized · unknown notification
         per version: compile · generate · roundtrip · generate-independent · roundtrip-independent
         malformed-source · unknown-method · describe-immutable · shutdown · after-shutdown · exit
model:   initialize(0.2.0-draft.1, JSON tuples) · initialized
         per model version: compile-model · generate-model · roundtrip-model
                            · generate-model-independent · roundtrip-model-independent
         bad-digest · shutdown · exit

Alternative: a fixed superset with skipped records. Rejected: the report would hold cases that were never run, and skip rules would be a second plan to check.

GKP-3. Legacy JSON is required; the model tier is required when claimed

Two of the three guests speak only MEP 0.1, so the required tier uses morphir.frontend.compile and morphir.backend.generate. A guest that claims 0.2.0-draft.1 and JSON model tuples must also pass compileModel and generateModel with morphir-json in a separate process. Alternative: require model transport. Rejected: the SDK fixture and Python 0.4.2 could not qualify at all.

GKP-4. IR comparison by stated rules, not bytes

Three rules only: object member order; the order of the IR 3 modules, types and values lists; the IR 4 type reference short form. Attributes, documentation and every other value still compare exactly. Alternative: the MoonBit kit's broader canonical form, which drops attributes and doc. Rejected: it would hide real differences in typed IR 3 output.

GKP-5. Generated files are checked by a round trip

The kit cannot fix generated bytes for every implementation of a language. Instead, after every generate case, the runner compiles the generated files whose extension the guest claims for the language, and the result must equal the expected IR. A model-tier round trip uses compileModel in the model session. The guest's frontend checks its own backend's output. The runner also generates from the kit's expected IR, so the backend does not depend on the frontend's output. Alternative: fixed bytes per language. Rejected: it binds a language to one implementation.

GKP-6. WASM guests run through the native worker host for now

The proving runs pass morphir extension worker of the native MoonBit CLI as the host, with --abi extism-kernel-v1 for the SDK fixture and Python, and --abi morphir-bytes-v1 for Gleam. Each run pins the CLI and the module with --identity-file. The profile itself does not depend on the host; a public stdio host (finos/morphir-moonbit#297) can replace it without a kit change.

GKP-7. Numeric request ids

The published Python 0.4.2 guest refuses a string JSON-RPC id ("mck:describe") with invalid type: string, expected u64, although JSON-RPC 2.0 allows string ids. The generic profile does not test id forms, so its ids are numbers counted from 1 in each process, as in the MoonBit profile. The Python profile keeps its string and u64::MAX id cases. The defect belongs to finos/morphir-python.

GKP-8. Supported claims formats only

The describe claim must use claimsVersion 0.1.0-draft.2 or the draft.1 field statementVersion 0.1.0-draft.1 (spec/mep/README.md), with no critical path other than that field. A claim of an unknown format cannot select a plan. Alternative: accept any string. Rejected in review: it would qualify guests whose claims this reader cannot interpret.

Risks and trade-offs

RiskMitigation

Migration plan

Additive. A new kit file and profile; no existing kit, digest or CLI flag changes. Rollback removes the kit file and the profile module.
