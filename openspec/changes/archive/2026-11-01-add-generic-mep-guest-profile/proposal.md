# Proposal

## Why

The shared MEP guest kit (`spec/mep/mck`, `morphir mck mep guest-run`) has two
profiles. `moonbit-model-stable-v1` needs Ion model transport.
`python-json-library-v1` needs the extension id `morphir-python` and a Python
frontend and backend. A guest built with `morphir-extension-sdk`, for example
the fixture of finos/morphir-moonbit#298, cannot pass either profile without
claiming the identity of another extension. The kit must show conformance, not
a list of known extensions. Bead `morphir-ukvn.5.64.36.15` asks for a generic
profile.

## What Changes

- New kit profile `generic-json-library-v1` in a new kit file,
  `spec/mep/mck/guest-generic-json.json`. It accepts any extension identity.
- The kit holds one fixed package (`mck/generic`, module `main`, two public
  Bool constants `ready = true` and `blocked = false`), one expected IR for
  `3.0.0` and one for `4.0.0`, and one fixed source set for each language that
  can express the package. The first languages are `morphir-fixture-flags`,
  `python` and `gleam`. A new language is a reviewed kit change that adds a
  source set and must compile to the same expected IR.
- Document URIs are relative to the source folder, for example `main.py`. They
  have no `src/` prefix and are not absolute.
- The runner selects the plan from the guest's own `describe` claim: the kit
  language, the IR versions and the model transport tier. Every claimed
  capability that the profile covers is tested. A claim cannot remove a
  required case.
- The required tier uses MEP `0.1` JSON methods (`morphir.frontend.compile`,
  `morphir.backend.generate`). When the guest claims `0.2.0-draft.1` with JSON
  model tuples, the model tier (`compileModel`, `generateModel` with
  `morphir-json`) is also required.
- Outputs are compared by meaning. Compiled IR must equal the expected IR
  under stated equivalence rules. Generated files are compiled again and must
  give the expected IR (round trip). The kit does not fix generated bytes.
- `report-check` rebuilds the plan from the recorded `describe` observation.
- The existing profiles, their kit files and their digests do not change.

## Capabilities

### New Capabilities

- `mep/generic-guest-profile`: the generic JSON Library profile of the shared
  MEP guest kit: kit contents, plan selection from claims, required cases,
  IR equivalence, round trip and report recheck.

### Modified Capabilities

None. `openspec/specs/` has no capability for the MEP guest kit.

- New kit file `spec/mep/mck/guest-generic-json.json` and its section in
  `spec/mep/mck/README.md`.
- `spec/mck/cli-contract.md`, `CHANGELOG.md`.
- No change to the MEP wire protocol, the CLI flags or the other kit files.
