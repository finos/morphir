Context

See proposal.md for the reason. Before this change, extension_registry_for in crates/morphir/src/extensions.rs registered two native providers: Gleam (always) and Elm (only when selected by id). Gleam was therefore the provider that every unselected compile, generate, playground and package scenario reached. The requirements are in specs/cli/builtin-providers/spec.md.

Goals and non-goals

Goals: the CLI builds without morphir-gleam-binding; every test that covered behavior other than Gleam keeps its coverage; docs point Gleam users to finos/morphir-gleam.

Non-goals: a new default provider; Gleam support through an installed extension in the Rust CLI; moving ecosystem/morphir-rust; removing Gleam from the spec models in spec/mep and spec/ir.

Decisions

PROV-1. No default built-in provider

The native Elm provider stays opt-in. Making it the default would change what every unselected Elm compile reaches, which is out of scope for a removal and would hide the installed morphir-elm extension. Alternative considered: Elm becomes the default. Rejected for that reason.

PROV-2. Drop the legacy selector alias

The morphir-gleam-binding to morphir-gleam alias existed only to reach the built-in. With no built-in, an exact installed id is the only meaning left, which the registry already gives.

CMD-1. Remove the roundtrip project check with the subcommand

prepare_compile took a roundtrip flag only for morphir gleam roundtrip. The flag and its "needs a project" refusal go with the subcommand. generate --from-partial-compile stays, because the generic generate command has it.

TEST-1. Port tests that do not test Gleam

A test moves to the native Elm provider when it covers compile, selection, output records, the playground or the provider pool. Generate tests move to an installed test backend. A test of the subcommand, the native Gleam provider or the alias is removed. The Elm frontend compiles types only, so ported sources use types.

PKG-1. Package examples stop after restore

morphir generate reaches installed backends only, and no backend is installed offline. The package scenarios therefore prove resolve, restore and update, and the frozen Gleam goldens go. The publish example compiles a native Elm type alias in place of the Gleam function.

MEP-1. The MEP contract tests read the committed IR

Decided by Damian Reeves on 2026-10-31 (option A). mep_contract keeps its coverage and wire-rule checks on spec/mep/generated/mep.ir.json and loses only the fresh-compile drift test. mise run spec:mep stops with a pointer. Alternatives: keep the provider until the tooling moves (blocks this change); delete the task (hides the gap). Bead morphir-sugs restores generation with the morphir-gleam extension on the MoonBit CLI.

SUB-1. Move the morphir-gleam pin only

ecosystem/morphir-gleam moves from aa2b7e2 to finos/morphir-gleam main, which holds the moved extension. The crate path in ecosystem/morphir-rust is no longer referenced, so that pin does not need to move here.

Risks and trade-offs

RiskMitigation
Users of morphir gleam lose the command in the next release.CHANGELOG and docs point to finos/morphir-gleam and the MoonBit CLI.
A playground on an empty home offers no provider.Installed extensions and a configured [frontend.elm] extension still work; the Rust CLI is being sunset.
spec/mep/generated/mep.ir.json can drift from mep.gleam.The coverage tests still read the IR; morphir-sugs restores the drift check.

Migration plan

Merge after review. Rollback is a revert of the pull request, which restores the path dependency and the old submodule pin together.
