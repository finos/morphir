add-bounded-model-access

OpenSpec design | 2026-11-09 | proposed for review | .NET and MoonBit first

Follow acme/orders from a completed compile to installed generated files. The package can grow beyond a WASM guest's memory ceiling; each stage still knows where its inputs live, which revision it is reading and how much work it can retain.

Context

See the proposal for motivation and scope. The existing v3.1 and v4 JSON/YAML document-tree contracts already settle paths, escaped names, dependency directories and file roles. This design changes how implementations consume those artifacts and adds an opt-in contextual encoding.

At the inspected revisions, Rust's tree source assembles the full tree before replaying events. MoonBit's reader accepts a map of every file's text. .NET's Ion tree reader opens individual files but returns a complete distribution. These are useful starting points, not evidence of bounded large-model generation.

Agreed direction: generation first, the configured workspace out root, file contexts, reversible compaction, .NET/MoonBit conformance first, and measured investigation of indexed lookup. Proposed mechanics: the envelope below, resumable access sessions, exact draft identifiers and qualification protocol. These remain reviewable choices.

TermMeaning in this design

Goals and boundaries

A caller can generate from supported v3.1 and v4 trees while retaining a bounded working set. Both host and guest are measured. Artifact outputs, inventories and indexes also have limits; moving the body to disk does not excuse an unbounded symbol map or output buffer.

The first gate covers native .NET and native MoonBit hosts, their in-process reader paths and a shared WASM generation fixture on each host. The same contracts admit later hosts. Evaluation, a live daemon, retained build generations, shared context imports and arbitrary subexpression splitting are later work. Frontend document-batch publication has a defined boundary but is not a first-delivery implementation claim.

The generation journey

OUT-1. Start with a producer's result

1. Compilation has finished. The generator finds the product.

The established Mill-style task convention gives each task a destination and a result record. Zig's install distinction also matters: working artifacts live under the out root; -o installs selected products elsewhere. Bazel's declared-artifact model informs the explicit dependency between stages, without adding a new build engine.

<out>/packages/orders/
  compile.json
  compile.dest/morphir-ir/manifest.json
  compile.dest/morphir-ir/pkg/acme/orders/domain/
    module.json
    order.type.json
    total.value.json
  generate/example.json
  generate/example.dest/

Follow the existing precedence: flag, environment, workspace setting, default. Use the declared workspace-member path even when its sources are reached through a supported symlink. Definition paths keep the existing escaping and bare @ dependency segment.

Alternative: scanning a conventional compile folder is convenient but can consume stale files or the wrong transform output. A result record supplies provenance and the IR descriptor. A tombstone means no usable product.

Observable requirements: model snapshots.

SNAP-1. Keep that revision alive through the last read

2. The first page is small, but the generator will ask for more later.

The host takes the producer's shared task lock before reading its record and retains it until generation completes, fails or cancels. A competing compile waits for the exclusive lock. The lifetime must span all lazy reads, not only initial discovery.

Explicit mutable directory inputs need a bounded capture into task-owned storage or equivalent immutable backing. Integrity checks must identify changed sources rather than mixing revisions. A trusted digest or stable captured bytes can bind the inventory; a byte digest does not certify semantic validity.

Alternative: retained content-addressed build generations allow concurrent recompilation, but require retention and garbage-collection policy. Start with the existing lock lifecycle, leaving that optimization for a later change.

READ-1. Ask for documents, not the complete distribution

3. The generator visits the model in pages and releases bodies.

The host provides a pure version-specific decoder behind an effectful reader. The reader pages through module/member inventory and reads selected logical documents. The guest retains only its bounded working set. Oversized inventories spill to disk; they do not move into a single ever-growing map.

inspect(snapshot)                 -> distribution description
listModules(snapshot, page)       -> bounded page + continuation
listMembers(snapshot, module, page) -> bounded page + continuation
readDocuments(snapshot, ids)      -> bounded document batch
release(snapshotLease)            -> backing resources can retire

These are conceptual operations, not prescribed language classes or final RPC methods. The role distinction between a type, a value, a definition and a specification remains typed. Existing semantic node addresses remain independent of document stems and aliases.

A structural pass can validate every file under bounded memory before generation. Opening an inventory alone cannot claim that unread bodies are valid. Semantic prerequisites are separate evidence tied to the exact revision and dependency context.

Alternative: assembling a full distribution is useful as a compatibility convenience for small inputs, but cannot satisfy this resource contract. A single huge inline module or definition can also exceed a bound; reject it precisely rather than silently inventing subexpression chunks.

NAME-1. Give each document an independently usable context

4. Repeated SDK references use one typed local alias.

The proposed contextual-document envelope has its own exact contextVersion: 0.1.0-draft.1. Its document holds an existing file-kind payload. Expansion removes the envelope and restores that payload's version-specific name spelling before ordinary validation.

{
  "contextVersion": "0.1.0-draft.1",
  "context": {"fqNames": {"q0": "morphir/SDK:basics#int"}},
  "document": {
    "formatVersion": 4,
    "name": "amount",
    "def": {"Public": {"TypeAliasDefinition": {
      "typeParams": [],
      "typeExp": {"Reference": {"fqname": {"$name": "q0"}}}
    }}}
  }
}

The expanded type reference is {"Reference":{"fqname":"morphir/SDK:basics#int"}}. The same table spelling can resolve to classic arrays in a typed v3 FQName position. The enclosing document still obeys v3 semantics.

Tables distinguish Names, package paths, module paths and FQNames. Entries contain fully expanded validated spellings. Alias references only occur in typed value positions; name-keyed map keys remain expanded in draft.1. A document literal containing {"$name":"q0"} is just a document literal.

A deterministic writer policy sorts typed spellings, allocates stable aliases and accounts for the encoded cost of every table and reference. It keeps a name expanded when aliasing increases size. The little example above illustrates syntax, not a measured saving.

Alternatives: prefix aliases can shorten FQNames but do not address repeated complete identities uniformly. Shared tables can improve tiny-file overhead but add retrieval dependencies. Begin with file-local tables, no remote context loading, no shadowing and no alias chains. Ion symbol tables are a codec optimization for symbols; repeated string-valued FQNames need separate treatment.

Observable requirements and the full worked example: name compaction.

MEP-1. Resume the operation between bounded calls

5. The WASM guest requests a working set and returns output chunks.

Use a new exact MEP draft, proposed as 0.2.0-draft.2, with access contract 0.1.0-draft.1. Existing 0.1 and 0.2.0-draft.1 exchanges keep their meaning. The canonical Gleam/Smithy contract and transcripts must fix final wire fields before SDK implementation.

Negotiate complete tuples including operation, semantic IR version, codec, model profile, layout, contextual encoding and access version. The host keeps preference order. A missing default is harmless when another offered tuple agrees; a required bounded mode is not silently downgraded.

The result is a tagged sum: continue, complete or failed. Continue carries bounded requests, chunks and diagnostics. Deliveries match request ids, snapshot identity and expected round. No stale response can append artifacts twice.

Alternative: reverse JSON-RPC calls or imported WASM host functions can expose a pull API directly, but add ABI and re-entry obligations. Resumable exchanges work with the existing byte-call shape. In-process adapters can expose the same behavior as an ordinary reader.

Limits, artifacts and compatibility
BoundWhat it constrains
Frame and batchOuter encoded bytes, decoded bytes, documents, contexts, depth, nodes and diagnostics, checked before oversized allocation.
Resident stateDecoded bodies, retained names, contexts, inventories, indexes and artifact buffers. Host caches and guest state are measured separately.
Cumulative operationTotal work, disk use, rounds and elapsed time. These remain finite while allowing model bytes to exceed resident memory.
Artifact chunkSafe relative path, contiguous offset, encoding, end marker and per-file/aggregate output allowances.

Stage chunks under the generation task. The host builds its file ledger incrementally on disk. It admits complete only when artifacts are closed and required validation passes. Failure leaves the task tombstoned and never installs partial products. Previously installed outputs follow the existing install contract; the previous mutable task destination is not promised to survive a rerun.

A small legacy-compatible model can still use a supported operation within its limits, with a protocol-fallback diagnostic. That run does not establish bounded-session qualification. Lossy conversion follows existing explicit permission and reporting rules, and converted revisions cannot inherit evidence automatically.

The future frontend path emits document batches into a host-owned stage and publishes a model descriptor only after complete. It reuses artifact ownership and validation rules; implementing it is outside the first generation gate.

Observable requirements: model access sessions.

IDX-1. Prove whether indexes avoid reading bodies

6. Ask which definitions reference an SDK name.

A dictionary answers what an alias means. It does not prove where it occurs, or that a fully spelled reference is absent. An occurrence index needs its own completeness contract. A location index needs exact source digests, byte ranges and the decoding context for each region.

dictionary: q0 -> morphir/SDK:basics#int
occurrences: semantic name -> definitions that use it
locations: definition -> document, range, context, source digest

General JSON objects remain unordered. A context-last document can require bounded spill or another pass. A separately declared streaming form requires the envelope version and context before the document. Seekable storage and independently decodable compression are also necessary for byte-range savings; a whole-file compression stream can erase that benefit.

Alternative: forcing context-first ordering on all existing JSON would change current acceptance rules. Keep general compatibility, explicitly negotiate streaming guarantees, and bind optional derived indexes to the exact encoded artifacts under the consuming task's destination.

The experiment compares scan, dictionary-only and indexed lookup. Include cold index construction, warm reads, unused aliases, literal references, reordered fields and recompaction. One full read to build or verify an index is a real cost and must be reported. A rejected hypothesis does not block bounded generation.

MCK-1. Let .NET and MoonBit establish the first evidence

7. Run the same cases, then inspect separate receipts.

The parent repository owns the corpus, frozen expected results and report contract. The kit keeps one runner. It is the Rust morphir mck today and is intended to move to the .NET or MoonBit host; that choice is made outside this change, so the cases and expectations are written as data any host can consume. .NET and MoonBit supply independent adapters. Initial runner work is limited to executing and checking these cases; Rust library/host adoption is deferred.

Freeze a tiny package's expected output before writing either adapter. A neutral test generator consumes signatures and body facts, including a value in the final page. Cross-host execution of the same WASM fixture has identical expected artifacts. A production generator compares its own target output across equivalent representations and only claims the paths it has qualified.

EvidencePassing observation
Representation correctnessPlain, contextual and expanded trees preserve v3/v4 semantics and produce the fixed expected artifacts.
Resource qualificationInput bytes exceed declared host and guest memory ceilings while measured peaks, resident data and output batches remain bounded.
Lifecycle correctnessRecompile waits for a lazy reader; cancellation releases it; stale rounds, contexts and indexes cannot change the selected revision.
Coverage scopeSeparate receipts name the .NET and MoonBit revisions, native hosts, in-process readers and WASM guest path. No claim extends to an untested host or backend.

Alternative: a tiny full-model round trip can establish codec correctness but not a large-model memory bound. Self-reported counters alone also cannot prove an enforced ceiling. Use host/runtime measurements, state their scope and leave unsupported measurement gates unproven.

Risks and trade-offs

RiskMitigation and remaining cost
Long generation blocks recompilation.Cancellation and leases are explicit. Retained immutable build generations can remove this contention later.
One body or inline module is too large.Reject it at the named document limit. A separate reviewed chunking contract would be needed to admit it.
A generator needs a global graph.Use bounded disk-backed indexes or declare a prerequisite the selected implementation can satisfy. The shared fixture does not qualify every algorithm.
Tables increase small-file size or shift costs into names.Account for table overhead, entry count and spelling length; alias only beneficial occurrences. Include compressed and uncompressed sizes in the experiment.
Offsets or reference summaries become stale.Bind them to exact artifact and context digests; rebuild or scan when optional indexes are invalid. Never infer completeness from dictionary presence.
Large output or many diagnostics exhaust memory.Bound chunks, spool ledgers, cap diagnostics and measure the complete host/guest path.
A protocol draft is mistaken for deployed support.Keep exact offers, generated transcripts, separate adapter receipts and explicit unsupported outcomes. Existing bare profiles remain unchanged.

Delivery and rollback

  1. Review these artifacts. Create the owning Beads epic after the existing shared database conflict is resolved; link discussion #214, related issue #965 and this change. No epic id was returned by the rejected local creation.
  2. Freeze the parent contract models, contextual examples, access transcripts and MCK expectations. Keep existing IR gates and the small generic guest profile.
  3. Implement .NET and MoonBit readers, name contexts and adapters in their own repositories. Keep separate issue and revision receipts. Do not update pinned parent submodules as an incidental step.
  4. Add resumable generation and disk-backed output on their native hosts, then qualify the same WASM fixture through both. Use focused failing cases before implementation and retain them as regressions.
  5. Run large resource qualification with enforced host and guest ceilings and publish the exact measurement scope. Run the index experiment independently. Reuse existing CI jobs; heavier qualification belongs in an existing manual lane or a justified manual run.
  6. Promote only the qualified tuple set. Roll back by disabling the new draft/profile offers and retaining ordinary artifacts and existing readers. Never offer an inline fallback that exceeds limits or silently discards model content.

The implementation work breakdown is in tasks.md. This proposal captures planning only. No implementation, merge or release is performed here.

Remaining tuning

Batch sizes, cache budgets, the corpus scale required to exceed measured runtime baselines and the disk index's private representation can be tuned without changing the specified identities, lifecycle or equality rules. Record the chosen values in qualification receipts. Shared contexts and new subexpression chunking require later proposals rather than an undocumented implementation choice.
