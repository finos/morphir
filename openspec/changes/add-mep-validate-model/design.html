Context

See proposal.md for the reason for this change. MEP 0.2.0-draft.1 has two model methods, compileModel and generateModel. Each needs its role capability and an admitted tuple of five members (operation, profile, codec, envelopeVersion, irVersion). The validator role has only the legacy morphir.validator.validate, with EmptyParams and OpaqueResult.

Constraints from the existing peers at finos/morphir-rust 99c0b676 and finos/morphir-moonbit 28271c61:

  • The Rust SDK (model/operation.rs, selected), the MoonBit guest (model_input.mbt, retain_input) and the MoonBit host (worker/session.mbt) read the selected tuple from output or input. The MoonBit host adds input to every request that is not a compile request.
  • All existing readers refuse an offered tuple whose operation they do not know: the MoonBit guest refuses the whole offer (invalid_support), and the Rust ModelOperation is a closed enum. finos/morphir-dotnet Morphir.Mep also has a closed union.
  • All existing hosts offer only the operation of the call.
  • The MoonBit wire reader refuses unknown members, so a member that is added to a record later can break existing readers.

Goals and non-goals

Goals: a validator method that a host can negotiate, admit and check with the same rules as the other model methods; a rule identity that does not depend on the extension or its location; no change for existing peers.

Non-goals: the payload of the legacy morphir.validator.validate; the transform payload; contract-defined references to model nodes in diagnostics (VAL-4); common validation options; how a host merges the diagnostics of more than one validator; SDK and host changes in other repositories.

Request flow

Decisions

Damian Reeves decided VAL-1 to VAL-6 on 2026-11-09, in review of the open questions of finos/morphir#1139.

VAL-1. The request carries an input tuple

ValidateModelRequest has model, input and options, as GenerateModelRequest has model and input. The extension checks that input is a session tuple and that the envelope matches it. Alternative rejected: no input, because the envelope and the method name give the five values. Then each SDK needs a separate admission path, and the MoonBit host, which adds input to every request that is not a compile request, needs a third branch. generateModel already accepts the same repetition.

VAL-2. Edit draft.1 in place, with an offer rule

The change edits 0.2.0-draft.1 in place, as finos/morphir#1101 (Diagnostic.data), #1115 and #1117 did. A host offers a validateModel tuple only to an extension whose describe result or recorded claims list at least one validateModel tuple. All existing hosts already offer only the operation of the call. Alternatives rejected: (a) publish 0.2.0-draft.2: drafts match exactly, so every peer must move at the same time, and draft.1 and draft.2 peers cannot connect; (b) a rule that readers ignore an offered tuple with an unknown operation: it changes every existing reader now. A later change can still add (b).

VAL-3. Host conversion for validation is lossless only

The host conversion rules for generation apply to validateModel, but the host never sends a lossy conversion, even when the user allows loss. A lossless conversion keeps the content, so the diagnostics are also correct for the original model. A validator that does not see all of the model can miss a problem or report a problem that the original does not have. Alternatives rejected: (a) no conversion for validation: hosts then differ, because the rule is not defined; (b) the full generation rule with allowed loss: the result of a lossy validation has no use.

VAL-4. Model-node references are deferred

This change keeps Diagnostic as it is. A validator fills location when the model has a source range, and otherwise names the node in message. A follow-up issue proposes an optional Diagnostic.node for all methods, as an IRI of the model node, in the style of SHACL sh:focusNode. Alternatives rejected: (a) a contract key in Diagnostic.data: data belongs to the extension; (b) a morphir: URI in location.uri: the required range then has no meaning; (c) Diagnostic.node in this change: it changes the diagnostics of compile and generate too, and needs its own review.

VAL-5. Rules have IRIs and codes

ValidatorCapability.rules lists ValidatorRule(id, code). id is an absolute IRI (RFC 3987), compared as a plain string. It gives a rule an identity that does not depend on the extension or its location, and RDF and linked data can use it directly, as SHACL names a rule with sh:sourceShape. code is the short diagnostic code of the rule, so diagnostics keep short codes, and the host maps (extension, code) to the IRI. The list is optional: empty means that the validator does not list its rules. The member is in the first version of the record, because the MoonBit reader refuses unknown members. Alternatives rejected: (a) the diagnostic code is the IRI: long codes in tables and editors, and validator codes look different from the codes of other roles; (b) no rule list: a later member can break strict readers; (c) a common options.rules selector: the contract then owns part of options, and a host can remove the diagnostics of a rule that the user turned off.

VAL-6. The IR is regenerated with the Gleam binding for now

mise run spec:mep stops, because the Gleam frontend moved to finos/morphir-gleam. The MoonBit CLI can run the Gleam 0.4.0 Wasm guest, but morphir extension compile always sends typesOnly: false. This change regenerates generated/mep.ir.json with a program that calls GleamExtension.compile of morphir-gleam-binding 0.4.0 (finos/morphir-gleam a529add) with typesOnly: true and IR 4. The same program gives a byte-identical IR for the unchanged contract on main. A --types-only flag on morphir extension compile in finos/morphir-moonbit closes bead morphir-sugs. Alternatives rejected: (a) commit the program here: the MoonBit route replaces it; (b) wait for a MoonBit release: it blocks this change.

Risks and trade-offs

RiskMitigation
A host offers every operation to every extension, and an existing guest refuses the offer.The offer rule forbids it, and no existing host does it (VAL-2).
The input tuple and the envelope can disagree.The extension refuses with -32602 (corpus label unsupported_tuple); MCK case model-0041 covers it.
Hosts cannot sort or link diagnostics by model node in a standard way.The follow-up issue for Diagnostic.node (VAL-4).
Others cannot repeat the IR regeneration exactly until bead morphir-sugs is done.The pull request names the program and its commit, and the byte-identical check on main shows that the method is correct.
The Smithy model cannot check that rule ids and codes are unique, or the full IRI syntax.A pattern checks the IRI scheme; the uniqueness rule is a GAP smithy-2qe.34.24 comment.

Migration plan

The change only adds items, and no host offers a validateModel tuple to an existing extension, so no peer must upgrade at the same time. SDKs and hosts add the method in their own repositories. An older host reads capabilities.validator from a newer extension as an extra member and ignores it. Rollback is a revert of finos/morphir#1139.

Open questions

  • How does an FQName become a model-node IRI? The follow-up issue for Diagnostic.node decides this (VAL-4).
