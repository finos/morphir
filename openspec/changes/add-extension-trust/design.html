Context

See proposal.md, "Why". This change builds on acquire-extensions-from-repositories (bead morphir-ukvn.5.64.34): its acquisition package, extensions/v1 layout, index format, publish workflow and admission workflow. The MVP already records what this change checks:

  • index entries carry the publisher identity (owner/repo and release workflow) registered by the owner;
  • morphir extension publish --release attaches a .sigstore.json attestation bundle beside each artifact, made by actions/attest;
  • morphir repository admit attests index.json on every change. That root states the digest of each per-extension history, so the attestation also covers the publisher identities and artifact digests in the histories.

GitHub artifact attestations are Sigstore bundles: a DSSE envelope with an in-toto SLSA provenance statement, a Fulcio certificate for the workflow's OIDC identity and a Rekor log entry. Public repositories use the Sigstore public-good instance. A MoonBit verifier is being proposed in moonrockz/moon-lander (worktree moon-lander/sigstore-verification).

Goals and non-goals

Goals: one trust decision per repository; one prompt per operation; unattended options for CI; verification at install only, with activation offline.

Non-goals: a Sigstore TUF client (the trusted root is embedded); signing in the CLI; trust for local-directory repositories; publisher repositories that cannot attest (private repositories below GitHub Enterprise Cloud).

Decisions

TRUST-1. The repository is the unit of trust

The user trusts repositories; each trusted index names the publisher identity for each entry. Trusting a repository trusts its owner's curation, so a new extension or a new publisher that the owner admits later installs without a prompt. A changed publisher identity for an extension the user already has asks again on update, for every repository including finos; --trust and --trust-all answer it in CI. The finos repository and its owner identity (finos/morphir and its admission workflow path) are compiled into the CLI as the default trust. For any other repository the owner identity comes from its index.json and is shown in the trust prompt (trust on first use).

Alternative: trust each publisher separately (rejected: more prompts for the common case; an owner who admits a publisher already vouches for it).

TRUST-2. Attestation is required for GitHub-hosted repositories

Once this change lands, an artifact from a GitHub-hosted repository without a valid attestation does not install, and an index without a valid owner attestation is searchable but not installable. Local-directory repositories stay digest-only. This narrows the 2026-10-17 note in morphir-ukvn.5.64, which made authentication optional: the user's trust decision names identities, and only an attestation shows that bytes came from them.

TRUST-3. A top-level trust command and shared options

morphir trust add|list|remove <repository>, stored in extensions/v1/trust.json. The MoonBit CLI has no package commands yet; when package trust arrives it can join this command. Every prompting command (extension install, extension update, setup, and compile and generate with on-demand installation) takes --trust <repository> (repeatable) and --trust-all.

SIG-1. Verify with the Moon-Lander Sigstore package at install time

The acquisition package calls the Moon-Lander verifier with the artifact digest, the attestation bundle, the embedded Sigstore public-good trusted root, the policy from the index entry (issuer https://token.actions.githubusercontent.com, source repository, signer workflow, hosted runners only) and the current time. The bundle comes from the .sigstore.json asset beside the artifact, or from the GitHub attestations API by digest as a fallback (with GITHUB_TOKEN when present). It is stored in the lock as an optional member of the MVP lock record. Activation does not verify signatures again; it rehashes the stored artifact.

SIG-2. Admission uses the same verifier

morphir repository admit verifies each release's attestations against the registered publisher repository and workflow with the same code users run, and admits nothing that fails. Releases admitted by the MVP are re-verified once when this change first runs; any that fail are withdrawn from the index with a recorded reason.

Risks and trade-offs

RiskMitigation
The Moon-Lander verifier is late or misses a target.The MVP works without it; this change starts when the package passes its conformance fixtures on native and js.
A renamed release workflow at a finos publisher makes CI updates fail.The prompt and the error name both identities; CI passes --trust finos after review.
GitHub API rate limits on attestation lookups.Prefer the .sigstore.json asset; use the API only as a fallback.
Trust on first use for non-finos owner identities.The prompt shows the identity; the record keeps it; a later change of owner identity asks again.

Migration plan

Group 1 (trust decisions and prompts) can land after the MVP's groups 1 and 2. Group 2 (verification) lands when the Moon-Lander verifier is published. Extensions installed before this change keep running; their next update goes through verification. The SIG-2 re-verification runs once in the finos admission workflow.
