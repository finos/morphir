Model-line instruction budget

Bead morphir-ukvn.5.64.36.33 · 2026-11-09 · Proposed

A WASM guest call on the model line gets 5,000,000,000 instructions, where the native engine meters them. This page says why the host can now give that budget, why the host keeps a lower maximum than the engine, and how the tests prove the budget above 231. See the proposal and the requirement.

Context

The budget sets how far a WASM guest gets on the native host, because WAMR meters each call. Bead morphir-ukvn.5.64.36.26 raised the model-line budget from 1,000,000,000 to 2,147,483,647. Damian Reeves first chose 5,000,000,000, but Budget::parse in moonrockz/extism 0.1.1 refused budgets above 2,147,483,647, because WAMR held the count in a C int. Bead morphir-ukvn.5.64.36.33 gave moonrockz/extism 0.3.0 a 64-bit counter in its vendored WAMR, and Budget::parse now accepts 1 to the Int64 maximum. Bead morphir-ukvn.5.64.36.29 already made the portable MoonBit guest linear in the number of values, so the larger budget is for large real models, not for a guest defect.

One call, from the limits to the engine

The session limits give the budget. Limits::host() has 5,000,000,000, and Limits::for_session keeps it on the model line and lowers it to the restricted Extism profile on MEP 0.1. The native launcher makes CallBounds::for_abi from the limits and starts the worker with --instructions 5000000000. The worker parses the option into CallBounds, and CallBounds::engine gives @engine.Budget::parse the same Int64. The Node and browser hosts give instructions=None, because their engine does not meter.

pub let max_call_instructions : Int64 = 9007199254740991L
let model_call_instructions : Int64 = 5000000000L

pub struct CallBounds {
  deadline_ms : Int32
  instructions : Int64?
}

Decisions

BUD-1. The model line has 5,000,000,000 instructions (Owner)

Damian Reeves asked for this budget. MEP 0.1 and a probe keep 1,000,000,000, and the call deadlines of 10 and 30 seconds do not change. A runaway guest on the model line still stops at the budget or at the deadline, whichever comes first. At about 7 seconds for 5,000,000,000 instructions on a developer machine, the 10 second deadline of morphir-bytes-v1 can come first on a slow machine.

BUD-2. The host keeps budgets from 1 to 253 − 1 (Owner, 2026-11-09)

The engine accepts the full Int64 range. The host keeps a budget that a JSON number and a JavaScript Number hold exactly, because the npm host and the JSON reports carry host values. 9,007,199,254,740,991 instructions are more than 70 days of run time at the measured rate, so the lower maximum takes nothing from a real call. Limits::new and the worker parser check the range.

BUD-3. --instructions takes decimal digits only (Call)

The parser refuses 0x10, 0b101, 1_000, +5, white space and an empty value, and it takes values that start with a hyphen, so that --instructions -1 gets the range message and not the message of the argument parser. The launcher always writes plain digits.

The end-to-end test uses 2,147,483,648, one more than a C int holds, and a 60 second deadline, so that the budget and not the deadline stops the call on a loaded runner.

Risks and trade-offs

  • The measurements in the extension guide were made at 2,147,483,647. The guide says so; they are not measured again here.
  • CallBounds::new does not check its value, as before. Repository code makes CallBounds only from checked Limits, from the worker parser, or with no budget.
