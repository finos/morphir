Scope and decisions

U1 specifies a first-class untagged Union expression, independent wire and semantic examples, and affected consumers. It does not implement a parser, codec, checker or backend. The binding input is the untagged-union section of ConceptualModel morphir-ukvn.7, stored draft 0.17. The delivery plan morphir-ukvn.7.9 still names draft 0.16; the Union semantics are retained in 0.17.

The public Type System draft carries the wire and semantic rules. This companion pins fixture interpretation and the inventory used by downstream tasks. Existing v4 rules, including decision 0005 on attributes, continue to apply.

A tagged declaration such as type IdentifierValue = Text String | Number Int creates constructors. type alias Identifier = String | Int names existing values and creates none. type A = B declares a nullary constructor B; type alias A = B resolves an existing type B. Only constructor lists accept a leading pipe.

Wire contract

{"Union": ["morphir/SDK:string#string", "morphir/SDK:basics#int"]}

{"Union": {
  "attributes": {"source": {"startLine": 1, "startColumn": 1, "endLine": 1, "endColumn": 20}},
  "alternatives": ["morphir/SDK:string#string", "morphir/SDK:basics#int"]
}}

The abstract node is Union(TypeAttributes, Array[Type]). Every authored Union has at least two listed alternatives; repeated alternatives count as entries. Readers accept compact and expanded forms, including expanded empty attributes. Writers omit empty attributes and use the compact form. Child nodes select their own spelling independently. A bare array is always a Tuple. There is no legacy Union spelling.

The expanded payload requires an alternatives array. Invalid arity, missing alternatives, non-array alternatives, malformed child types and multiple node-kind wrapper keys are rejected. The ordinary v4 node/attribute grammar applies recursively. Decoders preserve order, duplicates, nesting and all attributes. JSON object member order is not a semantic distinction; array order remains observable as authored provenance.

Union occupies an existing Type position. An alias definition still uses TypeAliasDefinition and its existing typeExp member; no new distribution, definition or value wrapper is added. This profile specifies JSON Type forms. A future Ion representation must be specified and qualified by its codec owner; generic retention of the conceptual AST is not that representation.

Semantic contract

RuleConsequence
Inclusive membershipA value belongs when at least one alternative accepts it. Overlap succeeds without selecting an arm.
Order, duplicates and nestingMembership and assignability ignore reordering, repeated equivalent members and associative nesting. Codecs retain the original tree. Structural equality and byte equality are distinct from semantic equivalence.
Annotations and refinementsPreserve union and member annotations separately. A union-level obligation applies to the whole union; a member obligation applies to membership through that member. Another accepting alternative may suffice. No simplification may erase obligations or provenance.
SubstitutionVisit every alternative recursively and preserve attributes. Substituting String for a in a | String yields two listed String alternatives. It is still valid; do not collapse it to an invalid singleton Union.
Aliases and opaque typesExpand transparent aliases when justified. Keep opaque nominal identities and visibility. Equal representations do not authorize conversion between distinct opaque types.
AssignabilityEach possible source alternative needs a justified destination type. For a union destination, each source alternative needs a justified destination alternative. Failure to prove a more complex inclusion is not permission to guess. No implicit numeric coercion or refinement solver is introduced.
NarrowingA member widens without conversion. A union narrows only when every alternative is assignable, or a checked membership guard proves the narrower type. Member-specific operations require that proof.

A guard checks actual type, structure and required refinements. It does not inspect a fabricated Union tag. In overlapping unions, rejecting one member does not identify a unique remaining arm. An unknown check authorizes neither execution branch. Higher-order membership, unresolved variables and unavailable semantic profiles are outside the initial concrete first-order checker unless a consumer explicitly qualifies them.

Decoding and unsupported checks

Typed membership starts with an interpreted value. Raw decoding must determine an interpretation. Several members accepting the same typed value is success; several distinct typed interpretations is ambiguity. Int 1 and Float 1 are distinct typed values, as are different opaque identities with the same representation. Never select the first successful decoder.

An explicit codec mapping may settle ambiguity, for example an agreed integer-token rule. It must be named, documented and independent of alternative order. Smithy member-tagged unions and JSON Schema alternatives do not automatically supply that mapping.

OperationAvailable evidenceResult
Typed membershipAt least one alternative proves membershipMember; no selected arm, even if another member is unsupported
Typed membershipEvery alternative was checked and rejectedNot a member
Typed membershipNo acceptance proof and at least one unsupported or exhausted checkUnsupported/unknown; cannot prove a negative
Raw decodingExactly one distinct interpretation and all alternatives accounted forDecoded value
Raw decodingTwo or more distinct interpretationsAmbiguous; explicit codec decision required
Raw decodingNo interpretations and every alternative rejectedRejected
Raw decodingAn unevaluated alternative could add an interpretationUnsupported; cannot claim uniqueness, unless an explicit encoding rule excludes it

Independent fixtures

cases.json is an independently authored reference-only corpus. environment.json fixes primitive names, aliases, opaque identities, refinement meaning and raw JSON profiles. assets.json pins their bytes. Expected outcomes are hand-authored from this contract, not generated by the implementation being tested.

typeRef is a fixture lookup into environment.types, not IR syntax. Other type objects are literal draft v4 Type JSON. A fixture typed value is a typeRef plus an illustrative JSON value, not a new serialization protocol. An opaque typed value describes evidence that the value already has that nominal type; it does not authorize construction from its representation. Consumers translate these descriptions through their existing test adapters.

Each case names an operation and an expected outcome. wireDecode compares the decoded node and canonical JSON; wireRoundTrip preserves the supplied types and listed properties. equivalent checks meaning separately from structural equality. substitute uses the supplied free-variable map. membership, assignable, guard, use and rawDecode apply the rules above. declaration distinguishes source declaration forms; projection, downgrade and emit describe required capability boundaries. Diagnostic reason strings are corpus categories, not mandated public API codes. A path on a wireDecode failure is a JSON Pointer into input.wire.

The default context is outside opaque owners, with no optional refinement interpreters available and resource limits not exhausted. Explicit case inputs override that context. The positive-int extension is a fixture-only versioned semantic profile, not a new core attribute: it accepts precisely Int values greater than zero. Provenance notes are descriptive and have no membership effect. Real consumers must not infer a profile's implementation from retaining its bytes.

The integrity test checks published assets, digests, fixture references, identities and HTML structure. It deliberately does not implement a second Union checker or treat expected outcomes as observed runtime results. Consumers should reuse MCK or their existing conformance adapter, retaining case IDs and recording implementation revision, profile, limits and actual outcomes. Passing integrity tests alone never grants Union capability.

Adoption and verification

U2 morphir-ukvn.7.9.1 consumes this contract for MoonBit native nodes, codecs, traversal, substitution, equivalence/assignability and safe exhaustive consumers. U3 morphir-ukvn.7.9.2 joins that implementation to conceptual projection/checking and qualifies ecosystem consumers. Existing task dependencies still apply. Closing U1 does not close either consumer task.

U3 should record separate evidence for retaining, reading/writing, projecting, checking and executing Union. Report unsupported operations and the exact revision/profile/limits tested. Before full schema retirement, include Union in the IR/SDK self-specification and shared compatibility corpus. Historical versions retain their prior definitions and refuse lossy downgrade.

mise run conceptual:fixtures-check
mise run fmt-check
bun test spec/conceptual/union/fixture-integrity.test.ts

The first command includes the new corpus alongside existing conceptual model and trait checks. The final command is the focused integrity check, not a runtime conformance suite. Execution results, review findings and landing evidence are recorded on morphir-ukvn.7.2 and the delivery-plan ledger.
