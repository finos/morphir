Scope

JSON operation validate-http-policy-boundary, exact version 0.1.0-draft.23. The implementation decodes original HTTP descriptor, submission and accepted-reply bytes using the production closed boundary. The runner keeps source bytes opaque and never implements HTTP negotiation, source decoding or capability planning.

The 55 fixed cases and expected projections are parent-owned and authored before production adapter execution. Source fixtures reuse independent capability-execution fixtures where applicable. No case ID or expectation is sent to the adapter.

Closed inputs

The exact input has kind descriptor, submit or submission-reply; encoding utf8 or hex; source; and context. Context has exactly authenticated fixture sessionId, the executions offer and captured draft.2 submission. Accepted replies are checked against that captured source, entry, arguments, policy and provider, including the complete selected public boundary. The context is trusted fixture authority, not proof of real authentication. Optional generate.prefix has repeat ASCII space and count 0–1048576, using the existing exact decimal count semantics. This compactly tests whole frames before whitespace normalization.

All fixture action syntax is validated before execution. Unknown operations or infrastructure members reject. Source text and opaque HTTP bodies remain implementation input, even when deliberately malformed.

Closed observations

Success has exactly accepted:true and policy:null for descriptors or strict/permissive for submissions and accepted replies. Refusal uses one bounded published production code. Closed root/member errors use workbench.host_shape, exact version/profile failures use workbench.host_version and workbench.host_profile, authenticated session mismatch uses workbench.execution_authority, scoped runtime/provider/policy/plan mismatches use workbench.host_selection_mismatch, and whole-frame excess uses workbench.host_input_limit. A malformed UTF-8 fixture uses workbench.host_utf8. These are production boundary codes, not an invented parallel taxonomy.

Bounds and checking

Existing shared framing limits apply: compact input and projection at most1MiB, corpus16MiB and1024cases, aggregate observations16MiB, report32MiB. Client/provider actions are at most32 and requests128. Fixed traces retain at most four accepted plans. Identity, plan and diagnostic limits retain UTF-16 semantics after schema code-point checks. Provider plan/receipt identities must agree, accepted owner-scoped execution and plan IDs cannot repeat, terminal values must be canonical, and observed worker exits cannot exceed starts.

One shared Rust runner performs capability negotiation, fixture validation, bounded observation validation and comparison. Independent saved-report checking recomputes the exact corpus SHA-256, ordered case inventory, capabilities, verdicts and qualification. Replaying expected responses proves checker infrastructure only.

morphir mck workbench run --kit spec/workbench/mck/draft.23 --adapter /path/to/adapter --report report.json
morphir mck workbench check --kit spec/workbench/mck/draft.23 --report report.json

Evidence limits

Controlled client effects do not establish authentication or actual execution. Actual provider traces identify the gateway, worker and provider used, and retain the selected runtime's bounds. Live browser, packaged Proton, physical transport fault and supported daemon regression checks need separate receipts. Frozen HTTP host draft.1, native mappings, execution receipts and earlier MCK14–22 remain separately qualified. Native compilation never enables a connected execution policy offer.
