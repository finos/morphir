Connected model originals

Wire profile 0.1.0-draft.1 · Morphir Workbench · Draft contract

This profile transfers an immutable model source inventory and, when requested, a separately identified semantic projection. A consumer can preserve and download exact JSON, YAML, Ion, tree files and empty directories even when it cannot inspect the model. Original bytes, semantic inspection and execution capabilities have separate meanings.

The profile name is morphir/workbench/model-originals. Its version is independent of the shared compatibility kit's version. Published MCK draft 29 covers offline local model inspection and export. It does not qualify this connected profile. The new connected MCK allocation, adapter observations and producer qualification remain required.

Workflow and authority

An authenticated connection captures a currently offered source and a project belonging to that source. The host resolves the existing source and project identities using its real provider and output grants. The caller supplies no filesystem path, companion list, revision or capture ID. A declaration or capability description cannot grant filesystem or execution authority.

flowchart LR
  C[Authenticated connection / current source and project] --> H[Real host authority / immutable snapshot]
  H --> R[Ready capture / inventory and separate byte roles]
  R --> O[Verify exact originals / preserve download]
  R --> P[Verify projection / current-model guard]
  R --> X[Release or close on abandonment]

The host captures the compile record, primary and declared companions under the same shared compile lock. A cooperating compile cannot change the owned snapshot. Projection uses those same frozen bytes after capture; reopening live files or making an unrelated v1 open call cannot supply its evidence.

Methods and shapes

Every object and union variant is closed in this exact draft. All displayed fields are required. Request and reply schemas include the complete JSON-RPC envelope. IDs use unsigned-u64 numeric token syntax, including 18446744073709551615; decimals, exponent spellings and negative zero are invalid IDs. Counts are exact mathematical integers evaluated before floating-point conversion. Duplicate members and ill-formed Unicode are refused.

Declared originals

The compile record's optional reserved morphirModelOriginals value has contractVersion and companions. Each companion is a relative file or directory root beneath the selected compile destination. The primary comes from the actual record descriptor. The writer publishes its positive companion policy atomically with the record. An explicit empty array declares no additional companions; directory scanning and the historical TaskResult.value do not create that declaration.

Absence, a valid declaration and an invalid declaration remain distinct. Primary-only capture does not claim completeness and ignores the out-of-scope companion declaration. Complete capture with no declaration returns unavailable/companions_undeclared without a handle; malformed declarations refuse before companion reads. Historical unknown record extras and old TaskResult decoding stay opaque and unchanged.

Ready origin is compiled with only record byte length, digest, schema, task, selected module and IR descriptor, or legacy-json with the exact project filename morphir-ir.json. Raw record data, install paths and unknown bookkeeping never enter the public summary. Legacy complete capture requires a declaration-capable writer.

Semantic projection

Projection is not-requested, unavailable with a closed reason, or available with codec morphir-json, byteLength, sha256 and actual formatVersion. Availability requires bounded serialization plus a valid header from the actual emitted projection. Missing or invalid emitted headers produce unavailable/invalid_model while originals stay ready. A descriptor's v3/v4 selector supplies neither source-header evidence nor emitted version evidence.

Source format evidence comes from the immutable primary snapshot, including semantic:none. Report an actual validated release or not-reported. A recognized unsupported release remains evidence. A semantic consumer separately verifies whether it can decode that release; protocol availability is not a claim of consumer support. The client verifies projection bytes and its current-opening guard before adopting a usable model. It keeps the last usable model owner separate from newly retained originals.

Release evidence uses canonical release SemVer with unsigned 32-bit components. Actual JSON headers recognize positive unsigned integer family aliases, including unsupported releases such as 2 and 99, or canonical release strings with major at least 3. A wire release such as 2.0.0 may therefore describe an actual numeric header 2. Prereleases, build metadata, floating-point aliases and out-of-range components are invalid header evidence. Recognition does not grant consumer compatibility.

JSON, YAML, Ion and single-file/tree interpretation use the existing host codec paths. Server compatibility compares decoded semantic content and verifies the producer's actual byte digest. Independent client fixtures use their own literal projection bytes. Transport compatibility does not require identical serializer ordering. BOM, CRLF, opaque sidecars, graph identity and rich conceptual metadata remain in originals.

Inventory and integrity

Include selected roots and every descendant, empty directories, empty files and unknown sidecars. Do not follow outside references, symlinks or special files. Intermediate ancestors outside a selected root are implicit containers; their other children are outside that capture. Refuse an invalid or over-budget capture as a whole.

Entries sort by unsigned lexicographic UTF-8 path bytes. File entries contain kind, entryId, path, byteLength and sha256; directories contain only kind, entryId and path. IDs are immutable and unique within their capture. Every page repeats the exact binding, capture and inventory digest. Counts satisfy entryCount=fileCount+directoryCount and file lengths sum to sourceByteLength. Clients verify all contiguous entries and all file digests before publishing a verified original owner.

Digest preimage is ASCII morphir/workbench/model-originals/0.1.0-draft.1, a zero byte, unsigned big-endian u32 entryCount, then each sorted entry. Each entry contributes kind byte 0 for directory or 1 for file, big-endian u32 UTF-8 path length, exact UTF-8 path, and, for files, big-endian u64 byte length and the 32 raw digest bytes. IDs and page boundaries do not affect the digest.

A page is the largest nonempty prefix fitting maxEntries and a complete compact UTF-8 reply measured with maximum-u64 ID. Include binding, IDs, digest and the actual next variant. No optional non-ASCII escaping or insignificant whitespace is emitted. More requires nonempty progress with the exact next index; complete is valid only at entryCount. Terminal index returns an empty complete page. An entry that cannot fit alone refuses rather than truncates.

For prefix sizing, render mathematical count values as ordinary unsigned decimal integers and use normal JSON string escaping. Counts still cross an exact mathematical-integer parsing boundary. The complete-frame limit bounds the actual received bytes; the pessimistic maximum-u64 ID and compact emission rules govern page selection.

Root paths permit at most 4,000 Unicode scalars, 16,000 UTF-8 bytes, 8,000 UTF-16 units and 128 components, with 128 descendant levels below a root. Components retain portable filename restrictions, including C0/DEL/C1, reserved devices, aliases and prefix conflicts. Root sets cannot overlap. The artifact profile's smaller 1,024-unit path limit is not reused.

Source and projection reservations share a host-wide 128 MiB pool; metadata, descriptors, record input, decode structure and output work have independent bounds. Reserve before effects. Projection capacity refusal can leave originals ready. A blocked worker retains its actual credits until it ends, even after client timeout or cancellation. These logical/requested bounds do not claim exact process RSS.

Connection ownership is Empty → Capturing → Ready → Released; Closed can retain only worker-owned pending cleanup. A second capture does not replace a capturing or ready owner. Repeated reads do not reread or recompile. Only the last released capture has same-connection idempotent release. Current-source revocation/replacement invalidates publication. Lost capture replies, uncertain exchanges and stale adoption close the owning connection or confirm release, without automatic capture retry or v1 reopen.

Validation and qualification

JSON Schema proves structural restrictions. Exact raw-number syntax, UTF-8 and UTF-16 bounds, path normalization, ordered complete inventory, measured reply size, digests, current authority, effect ordering and cleanup require semantic checks in the existing shared MCK. Schema examples or checker controls cannot establish production adapter compatibility.

The independent source packet preserves 49 wire scenarios, 60 preceding model scenarios, 35 inventory/conceptual additions and seven discovery mappings. They are unchanged review inputs, not a new executable compatibility runner or claimed producer results. Later reviewed header and resource decisions remain required. The connected server/client operations need a fresh exact MCK allocation; draft 29 is not extended.

The Rust checker's lossless transcript boundary reconstructs actual raw replies from literal text or bounded literal/repeat segments. It checks the complete expanded frame budget before expansion, then verifies the independent capture request and session, every original, projection semantics and the requested release acknowledgements. A 1,820,899-byte saved control replays 180,245,492 bytes of read frames for separate 64 MiB original and projection streams. These are checker controls, with explicit caller-supplied saved-byte, expanded-byte and exchange-count bounds. Expanded-frame accounting is separate from decoding work and host retention. The final connected MCK input/report vocabulary and policy limits still require the complete profile integration.

Compact source fixtures use a closed, flat byte vocabulary: lowercase hex, UTF-8, repeated bytes, wrapping cycles, chunk-indexed bytes and concatenation of atomic parts. The checker validates exact decimal counts, every literal and the complete expanded byte length before decoding literal buffers. Pattern expectations compare directly with actual bytes without generating a second source buffer. Caller-supplied recipe limits are separate from the retained original's 64 MiB bound, so an oversized input can exercise a source-limit refusal without becoming an accepted original expectation.

Original-source expectations also require independently authored primary and companion designations and the primary's source-header status. The checker compares the exact root kinds and paths and the reported release or absence of a report before accepting inventory and byte evidence. A self-consistent inventory cannot justify swapping the primary with a companion. Projection availability, projection release and consumer support remain separate from the primary's source release.

The independent peer-input helper supports bounded flat read runs. It matches each literal request's attempt, target, offset, maximum and exact unsigned request ID before rendering one authored reply from input fixture bytes. Complete ranges and byte-work bounds are checked before any row is rendered. This compresses authored input only. Every production pending effect, actual request and reply, cancellation, adoption and cleanup still needs measured evidence through the shared runner. Per-run byte counts do not establish whole-case work limits or runtime qualification.

The unchecked items are required before declaring this connected profile qualified. No runtime capability advertisement, SDK dependency selection or production authority is introduced by this document.
