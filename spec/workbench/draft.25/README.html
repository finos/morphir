Scope

JSON operation run-http-policy-provider, exact version 0.1.0-draft.25. The adapter performs real loopback HTTP requests through the production gateway, production provider, actual Node workers and selected Scheme evaluator. The upstream authentication endpoint is a controlled dependency. Claims about a production Rust daemon, another provider, another runtime or packaged platform do not follow.

The 29 fixed cases and expected projections are parent-owned and authored before production adapter execution. Source fixtures reuse independent capability-execution fixtures where applicable. No case ID or expectation is sent to the adapter.

Closed inputs

The exact input has opaque submission and closed actions. Initial authentication role is session. Actions session, submit, submit-lost-reply and shutdown have no other fields. Wait, query, cancel, release, query-lost-reply and release-lost-reply have a zero-based execution index 0–3. Authenticate has nullable sessionId and changes the controlled upstream endpoint. Replace-submission has opaque submission and only changes the caller fixture for future submits. At most four submit attempts occur. A literal providerId equal to provider resolves once to the actual provider ID returned by the first descriptor. Other provider IDs remain untouched. No version, policy, runtime or source rewriting is allowed.

All fixture action syntax is validated before execution. Unknown operations or infrastructure members reject. Source text and opaque HTTP bodies remain implementation input, even when deliberately malformed.

Closed observations

The projection has requests, executions, workers and nullable infrastructure failure. Request summaries record operation, actual HTTP status, bounded error code or null, and addressed execution index or null. Wait performs actual queries until a terminal receipt and emits one final wait summary. Lost-reply operations invoke the real operation then physically discard response delivery; their summary has status:null and code:null. A trusted observer can retain the actual accepted plan and receipt after delivery loss. This is instrumentation, not recovered client knowledge or a claim of a physical network fault. Executions retain actual plan, last observed receipt and release success. Actual host/provider/initial session IDs normalize to fixture roles host/provider/session, and accepted execution/snapshot/plan identities normalize by acceptance order, preserving relationships. Changed authority is never normalized back to the original role. Workers record actual started/exited counts and policies read from actual posted selected requests. No predicted transition substitutes for observation. Shutdown produces no HTTP summary and preserves the last observed execution receipt.

Bounds and checking

Existing shared framing limits apply: compact input and projection at most1MiB, corpus16MiB and1024cases, aggregate observations16MiB, report32MiB. Client/provider actions are at most32 and requests128. Fixed traces retain at most four accepted plans. Identity, plan and diagnostic limits retain UTF-16 semantics after schema code-point checks. Provider plan/receipt identities must agree, accepted owner-scoped execution and plan IDs cannot repeat, terminal values must be canonical, and observed worker exits cannot exceed starts.

One shared Rust runner performs capability negotiation, fixture validation, bounded observation validation and comparison. Independent saved-report checking recomputes the exact corpus SHA-256, ordered case inventory, capabilities, verdicts and qualification. Replaying expected responses proves checker infrastructure only.

morphir mck workbench run --kit spec/workbench/mck/draft.25 --adapter /path/to/adapter --report report.json
morphir mck workbench check --kit spec/workbench/mck/draft.25 --report report.json

Evidence limits

Controlled client effects do not establish authentication or actual execution. Actual provider traces identify the gateway, worker and provider used, and retain the selected runtime's bounds. Live browser, packaged Proton, physical transport fault and supported daemon regression checks need separate receipts. Frozen HTTP host draft.1, native mappings, execution receipts and earlier MCK14–22 remain separately qualified. Native compilation never enables a connected execution policy offer.
