Contract

This kit qualifies the exact worksheet source/range/value profile. Negotiate suite workbench, contractVersion 0.1.0-draft.27 and JSON framing. All earlier supported kits and fixed bytes remain unchanged.

{"op":"capabilities","suite":"workbench","contractVersion":"0.1.0-draft.27"}
{"suite":"workbench","contractVersion":"0.1.0-draft.27","binding":"implementation","language":"moonbit","operations":["worksheet-evaluate","worksheet-validate"],"formats":["json"]}

Independent operations

OperationInputObservation
worksheet-evaluateExactly {request: rawJsonText}Actual production pipeline report, or stable boundary-invalid code.
worksheet-validateExactly {request: rawJsonText, report: rawJsonText}Complete accepted canonical report, or boundary-invalid code. This must call production validation without running Scheme.

Both return {status:"ok",value:report} or {status:"invalid",code}. The runner leaves input strings opaque, so malformed/duplicate JSON, ill-formed UTF-16 escapes and hostile numeric spellings reach production decoders. Closed MCK operation wrappers are bounded separately at 8 MiB of compact JSON. Adapter request framing permits a further 1 KiB; this is independent of the production 2 MiB bound on each raw document. Arbitrary invalid strings can expand sixfold when escaped and need not fit this wrapper budget. Older drafts retain their existing limits.

The parent runner owns literal source, expected offsets/values/failures and comparison rules. It never evaluates Scheme, derives expectations from adapter output, or passes expected answers/case IDs to the adapter. Typed payload validation reuses the frozen parent terminal/value schemas and independent projection guards. Successful report validation is not inferred execution.

Qualification scope

The complete corpus contains 109 cases (47 evaluate and 62 validate). Evaluate and validate are independently scoped subsets with their own byte hashes. An adapter may advertise either or both operations. A subset claim qualifies only its matching subset; unsupported full-kit records prevent full qualification.

Coverage includes exact integers, float bits, UTF-16 text/character/ranges, CRLF/trivia/datum comments, definitions and fresh-run isolation, unavailable Scheme projections with continuing evaluation, parser/runtime failures and budgets, shared nested-vector expansion stopped before unbounded preview/projection traversal, repeated wide integers charged against encoded bytes before constructing a whole row, source/revision identity, malformed raw input and forged report boundaries. Independent report checking rejects altered captures, values, offsets, identities, inventory or result claims.

Evidence boundaries

The fixed supplied cancellation, timeout, output-budget, large typed payload and ModelError reports exercise validation only. The local Scheme language currently exposes no recognized SDK ModelError constructor; these structural cases do not claim actual evaluator projection of ModelError. Actual browser worker cancellation, stale-revision editor guards, packaged Proton and supported OS behavior need separate runtime tests and receipts. A replay adapter used in runner unit tests proves infrastructure consistency only and never qualifies a product.

Profile schemas enforce structural constraints. Production validation checks parsed form inventory; the independent parent runner validates literal expected observations and their source slices without embedding a second Scheme reader or execution engine.
