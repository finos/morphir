Compatibility

This additive profile is offered as an existing provider capability name/version entry. Connected protocolVersion 1, initialization, all legacy methods and PlaygroundArtifact serialization remain frozen. Exact canonical SemVer draft selection is mandatory before invoking a backend. Other providers default to unavailable. A selected-profile failure never triggers legacy regeneration. The documented SDK artifact binary flag already means standard base64; this profile changes no SDK schema.

Wire contract

All objects are closed. Requests and replies reject duplicate members at every nesting level before serde or JSON.parse can discard evidence. Strings must be well-formed Unicode. IDs, provider/session identities, targets and IR-version selectors contain 1–128 UTF-8 bytes and exclude C0, DEL and C1 controls. Their spelling is opaque, not a filesystem location. JSON Schema maxLength cannot establish the UTF-8 bound, so semantic decoding also checks bytes. Actual producer versions use canonical SemVer, with no lenient prefix. Each parsed major, minor and patch component is at most 9,007,199,254,740,991, the largest exact integer shared by the Rust semver and TypeScript @std/semver libraries. Prerelease and build identifiers retain their literal SemVer string semantics, including large numeric prerelease identifiers. This bound belongs only to this artifact profile and does not change SDK or IR version contracts. IR selectors retain existing semantics, including the selector 4.

Generation options must be a JSON object of named SDK options. Arbitrary nested JSON values, including literal keys, are preserved. Non-object options are refused with artifacts.invalid_request before reserving host capacity or invoking the backend. Legacy generation methods retain their existing behavior.

Ready includes status, profile, contractVersion, sessionId, providerId, generationId, actual producer {id,version}, selected target, irVersion, ordered artifacts [{id,path,kind,byteLength,sha256}] and diagnostics. Kinds are utf8-text or binary. Failed includes only status:failed, profile, contractVersion and diagnostics. No failed response contains a partial inventory. The chunk content is canonical padded standard base64; length follows from decoded bytes, nextOffset equals offset plus that length. No independent EOF flag exists.

Byte offsets and counts accept mathematically integral JSON numbers, including 1.0 and 1e0. Raw decimal tokens are checked before floating-point conversion. Fractional values, nonzero underflow tokens, negative nonzero values and values outside the field's bounds are rejected. Negative zero denotes zero. JSON-RPC request IDs retain the existing connected-protocol u64 syntax and uniqueness rules.

Byte and path semantics

Text retains String::as_bytes exactly, including BOM, NUL, CRLF and final newlines. Binary decodes the SDK's standard base64 and requires exact encoder round-trip spelling, including padding and zero unused bits. Preflight derives exact decoded lengths without allocating decoded output. No content is treated as an encoded Morphir model. SHA-256 is computed from retained bytes; wire digests are exactly 64 lowercase hexadecimal digits.

Reuse morphir_distribution::RelativeArtifactPath and Sha256Digest. Paths contain portable forward-slash components, at most 4096 UTF-8 bytes and 1024 UTF-16 units total, each component at most 255 bytes and 255 UTF-16 units. Reject C0 controls U+0000–U+001F, DEL U+007F and C1 controls U+0080–U+009F, forbidden characters, dot components, backslashes, device names including COM/LPT superscript digits, trailing dots/spaces, duplicate paths, normalized case aliases, parent-directory aliases and file/directory prefix conflicts. Path hints are never joined to a host output root. Collision keys are NFKC → full default casefold → NFC, with unicode-normalization 0.1.25 Unicode 17.0.0 and unicode-casefold 0.2.0 Unicode 9.0.0. These distinct table revisions are part of this exact profile.

Reserve a generation slot before provider invocation. One separate host invocation credit permits at most one artifact producer invocation and its response conversion at a time; another concurrent invocation refuses with artifacts.capacity before reaching the backend. Existing retained generations and reads remain independent. Reserve exact decoded bytes after preflight and before decoding. Validate the entire inventory and measure the complete encoded manifest plus diagnostics before Ready. Use the largest u64 request-ID wrapper when validating retained manifests, so later serialization fits every permitted request. Reject oversized diagnostics using a fixed bounded failure; never echo oversized content recursively. Reservations roll back on every failure. Decoded reservations include in-flight conversion and retained buffers. SDK strings, existing generator allocations, networking buffers and client ZIP working memory have separate ownership and are not claimed to fit inside this decoded-byte counter.

Authority and lifecycle

Every call requires the initialized authenticated connection and its currently offered exact profile/provider. Cookie, Host and Origin checks remain unchanged. One active generation per connection moves Empty/Released → Generating → Ready. Failures restore Empty. A second generation never silently replaces active output. Capture actual resolved producer metadata from the same single bounded SDK invocation used to produce artifacts. Reads and releases never invoke the backend again. Ready bytes are immutable even if the registry later changes.

Read min(maxBytes,length-offset) with offsets inside the advertised file. Repeated identical reads return identical bytes. Offset equal to EOF returns an empty chunk; beyond EOF refuses. Wrong generation/artifact IDs or another connection's handles refuse. Release drops all bytes and reservations, preserving only the last released identity for same-connection idempotence. Starting a new generation supersedes that last-release record. Connection/session closure or host shutdown drops reservations through ownership. A lost generate reply requires closing the owning socket, without automatic regeneration. Generation remains bounded by the existing synchronous invocation timeout; stopping client waiting does not prove remote generator interruption.

Generated bytes, retained bytes, verified client bytes, saved downloads and published files are distinct states. This service writes no files, installs no packages and promises no durable restoration. Clients verify captured context after every await, length and independent digest before any downloadable Blob/ZIP entry, and release the exact captured generation. Strict UTF-8 preview never becomes a re-encoded download payload.

Errors

Invalid request/authority/lifecycle calls return existing JSON-RPC errors with bounded messages and artifact data {profile,contractVersion,code}. Generation, SDK conversion, capacity and manifest-budget failures return Failed diagnostics with no inventory. Stable codes are artifacts.invalid_request, artifacts.invalid_identity, artifacts.invalid_range, artifacts.invalid_path, artifacts.invalid_path_set, artifacts.invalid_content, artifacts.file_count, artifacts.file_size, artifacts.set_size, artifacts.reply_limit, artifacts.capacity, artifacts.active_generation, artifacts.unknown_handle and artifacts.unavailable. Provider runtime errors use artifacts.generation_failed. Oversized replies use one error diagnostic with code artifacts.reply_limit, message Artifact reply exceeds its limit., and location:null. Diagnostics retain existing required severity, nullable code, message and nullable location fields; severity is error/warning/info/hint.

Qualification boundaries

The parent shared Rust MCK owns independently authored expectations and scoped server/client claims. The artifact evidence draft is 0.1.0-draft.28, allocated after worksheet 27 landed. Its artifact-server kit is an explicitly scoped claim; complete asynchronous client and real runtime qualification remain required. Native-direct evidence and installed-process evidence are recorded separately. The landed morphir-rust response policy explicitly permits at most 385 MiB of encoded response only for the SDK morphir.backend.generate method selected by GeneratedArtifacts. Legacy replies remain capped at 64 MiB, and request/discovery bounds remain unchanged. Unsupported sources refuse this policy. Artifact generation uses a fresh checked Session and call_once, with no pool reuse or automatic retry. NativeDirect retains its existing one-shot typed path. A timed-out artifact call drops only its owned connection; it does not abandon an independent legacy pooled guest. Independent actual installed-process regression covers four indexed 16 MiB binary files, four 16 MiB NUL text files, per-file/aggregate one-over conversion refusal, literal IR/options, lost replies, timeout invocation count one and measured child cleanup. This is a process/provider regression, separate from the NativeDirect authenticated shared MCK lane. The separate installed-process authenticated-host regression also reads the full 64 MiB binary set over bounded socket chunks and checks fixed digests, captured context, handle ownership, release/disconnect capacity and process exit. Its launchable host fixture uses the same BoundUiHost for the pending browser client qualification. Upstream TypeScript, actual Chromium and packaged Proton saved-file/ZIP comparisons remain required. A preview, a manifest digest copied as expected, or a download click does not qualify saved bytes.
