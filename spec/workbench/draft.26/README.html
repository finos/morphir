Scope

This exact offline draft adds two independently qualified operations: transcode-invocations and compare-values. The shared Rust MCK owns source fixtures and fixed expected projections. An explicit adapter exercises its production implementation. The runner never decodes an input invocation suite, performs the comparison or derives expectations from adapter output.

All outer messages use JSON and negotiate only this exact draft, operation subset and formats:["json"]. The source and target codecs inside the transcode operation are separately named. This kit adds no runtime capability, live protocol operation, provider authority, worksheet contract or packaged-platform claim. Historical kits and live profiles remain unchanged.

Invocation transcoding

Input is the closed object {sourceFormat,source,targetFormat}. Both formats are exactly json, ion-text or ion-binary. Text source uses {"utf8":"…"}; binary source uses {"hex":"…"} with lowercase, even-length hexadecimal. Framing validation bounds these opaque sources; semantic decoding belongs to the adapter.

  1. Decode the supplied bytes with the production invocation-suite decoder for sourceFormat.
  2. Encode that suite with the production encoder for targetFormat.
  3. Decode the actual encoded output bytes with the production target decoder.
  4. Project the redecoded suite through the production tagged JSON projection and return {targetFormat,invocations}.

A successful observation is {"status":"ok","value":{"targetFormat":"ion-binary","invocations":…}}. The runner validates the frozen morphir-invocations-v1 projection, bounded identities, distinct calls, exact numeric spellings and rich values, then compares with the independent expected suite. Record fields compare by name; invocation/list/tuple ordering and extension bytes remain exact.

No canonical Ion byte sequence is promised. Ion permits multiple valid encodings; the required property is preservation of the semantic suite through an actual reverse encoding and target decoding. Extension bytes in the JSON projection are compared exactly for each fixed fixture. This is not a general promise that arbitrary noncanonical extension encodings survive an Ion decode/re-encode byte for byte.

Typed value comparison

Input is the closed object {actual,expected,comparison}. Operands are opaque tagged JSON until the adapter decodes them through its production typed-value decoder. The comparison policy is {"profile":"morphir-comparison-exact-v1"} or {"profile":"morphir-comparison-approximate-v1","absolute":number,"relative":number}. Negative tolerances reach the implementation and are rejected as execution.comparison_tolerance.

The production comparator and mismatch locator return {matches,mismatchPath}. A match requires a null path. A mismatch requires a JSON Pointer string; the empty string denotes the root. The runner checks these observation invariants and fixed expected values, without evaluating the comparison itself.

Fixtures distinguish normalized Decimal equality from preserved codec scale, exact integer values, Float64 bits and explicit approximate tolerances. Signed zero and unequal NaN payloads remain distinct even under approximate comparison; nonfinite values do not gain approximate equality. Records ignore field order, nested mismatch paths escape ~ and /, and constructor ownership remains meaningful. Result.Err is ordinary data, distinct from an SDK model-error value. This is comparison evidence for these fixed cases, not universal SDK or evaluator qualification.

Fixtures and evidence

The parent-owned corpus covers all nine source/target combinations for scalar, rich and extension-bearing suites. Rich fixtures include large exact integers, Decimal scale, Float64 signed zero and NaN payload, isolated UTF-16 units, records, constructors, Maybe and Result. Negative fixtures cover malformed JSON/Ion/binary input, duplicate members/calls, identity and argument limits, invalid values and bounded evidence expansion.

Binary fixtures were authored from the published Ion 1.0 binary grammar: version marker, type/length descriptors, VarUInt/VarInt, local symbol tables and annotation wrappers. They are fixed source bytes, separate from the expected normalized suites. Neither fixture bytes nor expectations come from the implementation adapter. The local authoring helper is not a second compatibility runner and is not part of the shipped kit.

Reports retain the corpus SHA-256, exact claim set and ordered observations. morphir mck workbench check reloads the corpus and recomputes every verdict. Changed values, extension bytes, mismatch paths, missing/duplicate records and forged qualification cannot establish compatibility.

Retained observations / report16 MiB / 32 MiB, unchanged shared supervision and cleanup requirements.

Semantic decoder rejection preserves a stable execution.* code with identity details removed. Lexical JSON errors map to workbench.invalid_json; lexical Ion text/binary errors map to workbench.invalid_ion. Invalid operation wrappers map to workbench.invalid_request. Infrastructure failures remain report phases, never model values or successful observations. Raw outer JSON rejects duplicate members and retains literal token kinds before typed admission, including private serde marker-shaped maps.
