# Immutable capability selection execution corpus

This exact `0.1.0-draft.19` kit has 69 parent-owned fixed traces for
[`run-capability-executions`](../../draft.19/README.md). Thirty-seven traces invoke the
real selected evaluator through a once-only owner claim; seventeen include
supplied completion validation/publication. Other traces inspect actual retained
state, validate refusal or establish ownership and claim behavior without running.
All original models, arguments, actions and expectations are inline in `cases.json`.

Expected observations were authored from the accepted execution-plan profile, existing
owner/receipt contracts and previously fixed draft.12 source/value cases before
comparison with the implementation. The parent owns expectations. Adapter output
never becomes a golden, and no case ID or expected result reaches the adapter.

The corpus covers omitted strict and explicit policy capture; physical caller
IR/suite/default edits and fresh projection ownership; actual untaken/reached
unsupported operations; once-only claims and stale plan/policy/runtime/provider
selections; mismatch precedence after claim; retained-source replans with fresh
identities and independent original executions; lost claim/query replies and inert
transport gaps; query/cancellation/release behavior; controlled evaluator
pre-cancellation; exact actual values and complete recursive custom boundaries;
returned/model-error/failed/cancelled terminals; independent cleanup; immutable
completion context, terminal replay/conflict and extension echo; source/boundary
startup refusals; and bounded publication of multiple retained executions.

Supplied-completion traces deliberately use a reached Hole model where useful.
They validate evidence without executing it and do not authenticate a producer's
execution, cancellation or cleanup. Unknown runtime/policy strings are binding
refusals before the typed owner; legitimate provider/plan/policy mismatches call
the real owner. After deliberately discarding a claim/query reply, a separate trusted observer
queries/describes the real owner for the action view. That instrumentation is not
a client-received reply and establishes no reconnect authority or recovered
delivery. A transport-gap action makes no owner call and cannot establish
reconnect authentication or synthesize a receipt. Real isolated worker/process
qualification remains separate and mandatory for a worker capability claim.

`aggregate-projection-limit-does-not-report-owner-rollback` submits and runs four
independent executions whose each valid Text result contains 99,999 UTF-16 units. Each
receipt fits its budget, while the final combined observation exceeds 1 MiB.
The explicit projection-stage refusal reports that evidence is unavailable,
without asserting rollback or an empty authoritative owner.

`0.1.0-draft.5`. The current runner refuses retired job-based drafts without translation. A passing report covers only this exact corpus, actual adapter and
runtime context. UI, HTTP/native offers, packaged platforms, generated targets
