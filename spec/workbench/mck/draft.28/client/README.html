Scope and evidence

The artifact-client operation in exact MCK 0.1.0-draft.28 qualifies the actual Workbench asynchronous transfer attempt, verified byte owner and download registry for morphir/workbench/artifacts 0.1.0-draft.1. It is a separate scoped kit from the unchanged103-case artifact-server kit. A pure manifest decoder does not satisfy this client claim.

The adapter drives production owners through controlled effects. The shared Rust MCK independently validates closed evidence, reconciles its raw outbound requests and compares it with102 source-authored fixed expectations. Expected values and case names are never adapter inputs. Byte recipes, whole-file hashes, previews and transitions were authored before adapter observations. This kit adds no remote method, publication write, durable persistence or SDK format change.

Each attempt captures provider/profile/session/target/IR, cloned caller JSON, source identity/revision/epoch and bound effect functions synchronously. It owns one authenticated connection. Initialization uses existing protocol v1. The controller generates once, reads every file in inventory order with maximum65536-byte chunks, hashes every complete file in order, releases its exact retained generation and closes its own channel before exposing a verified owner. Empty files require one handle read. This maximum-chunk operational scope does not restrict other clients permitted by the wire profile.

Every connect, initialize, generate, read, digest and release promise can be held, resolved or rejected. Staleness and cancellation are checked after awaited work. Pending old A and completed new B retain distinct channels and owners. A late A result can release only A. Explicit registry clear/replacement invalidates old download references. Changing current context alone does not revoke an already completed verified owner; application source reconciliation supplies that separate policy.

Closed controlled inputs

Input schema defines at most4 attempt definitions and512 actions. Effects are referenced by attempt, sequential index and actual kind. A delivery must match an existing unsettled effect before data expands. Each case starts every definition exactly once and finishes every run/cancel/effect promise with all owned channels closed. Only intermediate checkpoints may be pending.

Recipes are literal lowercase hex, cycle-u8, repeat-u8 and chunk-indexed-u8. The indexed formula is byte[i]=(i modulo256) XOR ((floor(i/65536)+seed) modulo256), so adjacent chunks differ. Raw hostile replies retain complete text or at most32 lossless literal/repeated-ASCII segments. JSON duplicates, exact numeric tokens and malformed escaped Unicode reach the actual production decoder without a lossy JSON intermediary.

Optional local repeated-ASCII values default to none. At most4 recipes and1048577 aggregate units apply to existing paths before construction, followed by at most8 explicit surrogate/nonfinite faults. Path steps must exist after pre-start caller replacements and earlier recipes/faults. A key fault must name a final existing object member. Shape validation requires no repeated-string or malformed-Unicode allocation. Typed input refusals distinguish ill-formed-unicode, nonfinite-number and request-limit.

Original bytes, preview and registry

Actual SHA-256 effects measure the buffers supplied by production. Final owner, download and decompressed ZIP evidence measures original bytes rather than copying manifest digests. A producer utf8-text declaration does not prove valid text. Whole-file strict UTF-8 validation preserves BOM and detects invalid suffixes beyond the visible prefix. Invalid text keeps its original bytes downloadable and returns invalid-utf8 preview.

Owner text/binary preview prefixes are at most65536 UTF-16 units/bytes. A text prefix never ends at a high surrogate. Registry preview allocation is equal per file: min(65536,floor(1048576/max(1,fileCount))). Binary view content is empty and has a bounded original-byte prefix. Download/ZIP references must match the actual current publication, file inventory and exact verified paths. Mutating a returned byte copy cannot modify the private owner. ZIP entry names, lengths and hashes are exact; container encoding need not be byte-identical.

Lossless and typed observations

Observation and evidence schemas require actual effect/settlement/close/cancel events, a checkpoint after every action, the current context, pending effects, registry state and terminal attempts. Verified results include actual manifest provenance and measured file inventory. Failure/discarded results expose no verified owner. Cleanup is closed: not-connected, not-retained, released exact generation, or connection-closed with known/unknown generation and a typed reason.

The checker independently parses outbound frames, validates capture/ranges/correlation and normalizes only valid request IDs to effect ordinals. Inbound reply behavior is qualified through fixed controlled-input expectations and actual terminal/effect evidence; this client checker does not claim to reparse unsaved inbound replies. Generation/artifact identities remain exact captured literals. Arbitrary caller IR/options keep private-looking keys and strings intact through live and saved boundaries.

Saved evidence retains bounded UI explanations losslessly. Compatibility comparison omits only generic other.message and registry refusal message, while comparing typed protocol/input/verification reasons, operation/outcome/cleanup and remote RPC messages exactly. A generic failure cannot satisfy a typed expectation. Archive encoded length is bounded evidence but excluded from compatibility equality; exact entries remain compared.
