Scope

This exact offline kit qualifies local model inspection and original-byte export through an explicit production adapter. The maintained Rust MCK owns corpus admission, comparison and saved-report validation. It never imports an implementation's model codec, migrates IR, runs a model or calculates expected IR from an adapter response.

JSON, YAML, Ion text and Ion binary are model representations inside a JSON MCK frame. Neither operation offers a connected model service, authenticates a provider, writes an output file or releases a model. Connected model ownership remains with morphir-etg2.22.1. Existing exact drafts through artifact draft.28 remain unchanged.

Evidence and comparison

Normalized IR is retained as a string so no host JSON decoder can first narrow its numbers. The checker parses it through the existing duplicate-aware exact JSON parser and compares the resulting generic JSON values. Whitespace and member order do not change the comparison. Integer and decimal tokens are preserved. The checker does not interpret Morphir nodes or derive metadata from IR.

Original export must match the captured source bytes, input format and provider ID. Length and SHA-256 are independently recomputed from bounded decoded hex. A rehashed replacement still refuses because it differs from the captured input. Inspection evidence binds to the captured provider and format, while every semantic field is compared to the fixed independent expectation.

Refusals are closed invalid observations with an enumerated stable code. Published YAML syntax/profile failures retain duplicate_member, unsupported_yaml_feature, invalid_yaml, invalid_type and invalid_literal. Other listed codes cover JSON/Ion, version and resource refusals. Invalid observations do not claim execution or successful typed model assembly.

Fixed expectation provenance

The initial model cases were authored from the v4 distribution/literal and YAML contracts, the v1–v3 classic Library layout, and published complete Ion originals before observing any production adapter output. The four exact-scalar additions pin IntegerLiteral 9007199254740993, DecimalLiteral 123.4500 and date-looking StringLiteral text. JSON and YAML originals use the same authored semantic IR. Original YAML preserves BOM, CRLF, comments and quoting; Ion originals retain their published enrichments and provenance.

Historical parity subsets select published parent-owned cases from drafts.12, .14, .17, .26, .27 and .28, retaining exact draft and operation identities. Source file digests, selected IDs and final subset digests live in the MoonBit fixture bundle's provenance.json. Raw JSON slices preserve opaque tokens such as 1e999. An initial Python copy error produced Infinity and was corrected directly from the published source before actual adapter runs; the expected verdict was never changed.

Separate physical YAML profile and document-tree fixtures pin requirements before their production readers run. Physical parsing evidence alone does not prove typed model import. The v3.1 tree cases retain exact source-version requirements instead of reclassifying them as v4 source documents.

Qualification

Public Rust API tests construct checker-positive controls from frozen expected evidence, then reject forged fields, missing and reordered records, provider/format changes, changed bytes even with a new hash, duplicate keys, near-integral fractional lengths and oversized reports. These controls prove checker behavior only. They are explicitly labelled checker-positive-control-only and never count as actual CLI or Workbench runs.

Actual adapter qualification is a separate run against the same immutable corpus. Bind each report to an explicit producer, exact operation/profile, input digest, source snapshot and artifact digest. Recheck the saved report with the maintained parent command. Headless file selection, stdin, publication, cancellation and platform acceptance remain Task 7 tests, alongside the historical policy, worksheet, artifact and connected-lifecycle kits.
