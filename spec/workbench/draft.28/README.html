Scope and compatibility

This exact draft adds separately scoped artifact-server and artifact-client operations to the existing shared Rust MCK. It qualifies the negotiated morphir/workbench/artifacts 0.1.0-draft.1 profile independently of all frozen prior evidence drafts. Connected protocolVersion 1, SDK artifact serialization and all previous MCK versions remain unchanged. Capabilities require suite workbench, this exact draft, JSON framing and only the operations actually supported. An unsupported operation never qualifies.

The server kit is an explicitly scoped contribution. It does not qualify a TypeScript decoder as a complete client. The campaign also requires the actual Workbench asynchronous transfer owner, actual process invocation, browser saved bytes and packaged Proton saved bytes. Those claims remain pending until their separate production adapters and runtime receipts exist. No publication, installation or durable recovery is added.

Bounded fixture inputs

The closed input contains a fixture and an ordered actions array. The fixture declares actual producer metadata, the offered profile state, success/failure completion, SDK artifacts and typed diagnostics. An artifact is binary-recipe, literal-binary for malformed-base64 cases, or utf8-text. Compact byte recipes are hex, cycle-u8 and chunk-indexed-u8. The indexed recipe is byte[i] = (i modulo 256) XOR ((floor(i / 65536) + seed) modulo 256), so adjacent chunks differ.

Actions connect authenticated sockets, initialize the existing session protocol, generate, start or receive a held generation, read a window, read-all, release, close, capture actual usage, or complete the controlled SDK producer. Raw actions preserve negative JSON bytes literally. Sized-frame actions append ASCII whitespace to a literal bounded prefix to test the exact 1 MiB generation and 16 KiB control frame limits without expanding the MCK input itself. All requested sizes and cumulative work are validated before starting an adapter. Every opaque raw action conservatively reserves a complete fixture expansion, because its literal bytes may invoke generation; the runner does not classify hostile raw JSON to avoid that charge.

Producer versions use a SemVer library in canonical spelling. Each major, minor and patch component is at most 9,007,199,254,740,991 for Rust/TypeScript interoperability. Huge numeric prerelease identifiers retain string semantics. Offset and count tokens are exact decimal numbers; nonzero underflow and fractions cannot round into an accepted integer. Negative request strings are deliberately opaque until the implementation under test decodes them.

Observed evidence

An observation is status ok with the captured sessionId, providerId and an ordered events array. Domain refusals are evidence inside the transcript, not infrastructure-invalid observations. Events record accepted/refused connections and initialization, raw generation/read/release replies, measured transfers, SDK producer controls, actual transport closure and actual host usage. Usage comes from the production read-only observer and the SDK backend invocation counter. Authentication refusal requires the actual status for its fixture: HTTP 401 for missing/incorrect cookie, HTTP 403 for Origin/Host refusal. A swapped status, reset, HTTP 503 or other transport failure is an infrastructure error.

A transferred event contains actual generation/artifact identities, each requested chunk's offset, nextOffset, decoded byteLength and SHA-256, plus the assembled byteLength and digest measured from actual returned bytes. Whole-file base64 is never inserted into a large observation. Small explicit read windows retain the complete raw RPC reply, whose canonical base64 and bytes are independently decoded by the checker. Empty files are complete with the SHA-256 of zero bytes and require no chunk.

The checker preserves raw JSON text until duplicate-aware exact-number parsing. It validates the complete closed RPC envelope, exact request ID, profile, context, producer version, portable path set, inventory limits and complete encoded reply with the largest u64 ID. RPC error codes are exact signed i32 integers. Mathematically integral decimal/exponent spellings normalize to the same integer; fractions, nonzero underflow and either one-over boundary reject. Parse-refusal replies may carry null IDs only as an error without a captured request ID. A transport-close event records actual closure rather than an invented RPC error.

Identity and byte reconciliation

Opaque generation and artifact IDs are canonicalized only after checking their UTF-8/control bounds, uniqueness, captured session/provider, and authenticated connection ownership. Source spellings are retained for path, producer, target and IR selector. Generation IDs normalize to a connection/capture alias; artifact IDs additionally include their manifest index. Canonicalization never hides a changed authority, path, inventory order, request ID, digest or byte count.

Every successful read refers to a live retained generation on its owning initialized connection. Offset plus decoded length equals nextOffset and never exceeds the advertised file. Read-all summaries are contiguous, complete and bounded by the requested chunk size; each fixed chunk digest and final digest must match its independent expected literal. A released or closed owner cannot produce a successful later read. Portable path checks use the pinned Unicode 17 NFKC, Unicode 9 full default casefold, and Unicode 17 NFC tables, including parent-directory aliases and file/directory conflicts.

For the eventual client role, kind utf8-text remains a producer declaration. Hash/length/context-verified original bytes stay downloadable even if strict UTF-8 preview returns InvalidUtf8. A preview failure must not cause byte replacement or re-encoding. The client adapter must exercise the actual asynchronous Workbench byte owner and its effect calls after every awaited generate/read/hash/release boundary.

Independent expectations

The server kit has 103 fixed cases. Eighteen original byte recipes, 57 independent read windows and two aggregate sets originate in the independently authored source receipt. Whole-file and chunk digests were computed before any adapter output and cross-checked with OpenSSL. Indexed chunks prevent a 65536-period pattern from hiding chunk reorder. Six literal 131072/131073 byte manifest/diagnostic fixtures preserve maximum-u64 request IDs and exact envelope hashes.

The corpus also covers Unicode/path limits, canonical base64, 256/257 files, raw integral/fractional/underflow offsets, literal serde marker objects, duplicate members, exact profile negotiation, initialization and HTTP/WebSocket authority, active generations, stolen handles, idempotent release, disconnect cleanup, host byte capacity, 64 empty retained generations, and a blocked actual SDK producer proving invocation-credit refusal and rollback. The source recipe and report mutation matrices remain under independent provenance.

The runner self-tests use authored evidence only to test runner/report mechanics and are explicitly infrastructure tests. They do not qualify a server implementation. Production qualification uses the real adapter executable and its separately saved report.

Client owner qualification

The separate 102-case client kit drives the actual Workbench transfer attempt, verified byte owner and registry through held/resolved/rejected effects. It covers source/caller capture, strict raw-wire refusal, full original byte integrity, preview bounds, download/ZIP registry reconciliation, cancellation and stale old-attempt isolation. Closed client input/evidence schemas and the shared Rust checker qualify this role independently of the server adapter. It adds no second compatibility runner.

Complete raw outbound frames remain saved losslessly; exact caller objects are parsed independently for comparison. Saved UI prose is retained but generic error/refusal messages are excluded from compatibility equality. Typed reasons, operations, cleanup and remote RPC messages remain exact. Local fixture paths, repeat/recipe work and canonical/raw reply expansion are guarded before allocation. The8MiB derived projection limit is distinct from the unchanged1MiB saved evidence bound.

Actual client reports and packaged-runtime proof are recorded separately. A source-authored infrastructure replay is not a production qualification. See the client specification for fixed provenance, precise bounds and pending gates.
